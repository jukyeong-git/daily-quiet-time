# UI 디자인 사례 비교와 적용

1. **비교할 질문을 정한다.** 요청과 기존 화면·컴포넌트를 살펴보고 사용자의 주된 행동을 한 문장으로 정리한다. 예를 들어 묵상 읽기 화면이라면 “작은 화면에서 긴 한글 본문과 날짜를 어떻게 배치해야 읽기 편한가?”를 기준으로 삼는다.
2. **서로 다른 서비스의 원문을 읽는다.** [awesome-design-md 사례 목록](https://github.com/VoltAgent/awesome-design-md/tree/main/design-md)에서 이 질문에 답하는 서비스 두 개 이상을 고른다. 각 서비스 폴더의 `DESIGN.md`를 열어 관련 항목을 확인하고 원문 링크를 남긴다. 원격 자료에 접근할 수 없으면 출처가 확인되는 로컬 사본을 활용한다. 확인한 사례가 부족하면 그 한계를 명시한다.
3. **같은 기준으로 비교한다.** 각 문서에서 관찰한 구체적인 선택과 그 차이를 짚는다. 읽기 화면이라면 제목과 본문의 위계, 읽기 폭, 작은 화면의 여백을 비교하고, 기록 화면이라면 입력 레이블, 포커스, 저장 상태를 비교한다. 각 선택이 이번 화면에 어떤 이점이나 불편을 주는지 설명한다.
4. **결정을 화면에 반영한다.** 사용자 요구와 프로젝트의 기존 UI를 기준으로 채택할 패턴을 고른다. 원문의 수치와 서체는 한글 콘텐츠와 화면 크기에 맞게 조정하고 기존 토큰과 컴포넌트를 우선 사용한다. 구현 요청이면 해당 화면에 적용하고, 설계 요청이면 선택한 값을 설계안에 명시한다.
5. **결과를 확인한다.** 실행 가능한 화면에서는 실제 콘텐츠를 넣어 모바일과 데스크톱에서 선택한 패턴이 의도대로 작동하는지 확인한다. 결과에는 참고한 원문 링크, 적용한 선택과 이유, 실제 확인한 범위를 짧게 남긴다.
